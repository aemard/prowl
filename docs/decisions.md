# Decisions and assumptions

One line each, with the reason. Product decisions from the brief are not repeated here.

- 2026-10-06 — Sections 3–13 of the brief were collapsed and unreadable to the orchestrator; conventions they may have defined (stack, design, agents, phases) were reconstructed from the visible sections and are recorded below.
- 2026-10-06 — Name "Prowl" kept: the only Chrome extension with that name (afjmhofmjbffpakdiiilmkcdclabhmmb, last updated 2012) was removed from the Chrome Web Store on 2023-08-12; caarlos0/prowl is a terminal tool, not an extension.
- 2026-10-06 — Ralph runs as one fresh-context subagent per iteration driven by the orchestrator, because nested `claude --dangerously-skip-permissions` sessions are blocked in this sandbox; `scripts/ralph/ralph.sh` is still provided for local runs.
- 2026-10-06 — Commits are authored by the maintainer and committed/signed by Claude so GitHub shows them as verified.
- 2026-10-06 — Preact 10.29 + @preact/signals instead of React: ~4 KB runtime keeps the side panel inside its JS budget; Preact 11.0.0 shipped 6 days ago, too fresh for the ecosystem.
- 2026-10-06 — TypeScript 6.0 instead of 7.0: 7.x drops the JS compiler API some tools (Astro check) still rely on.
- 2026-10-06 — Plain Vite 8 multi-entry build with a generated manifest instead of CRXJS/WXT: fewer dependencies (supply chain) and full control of the MV3 output.
- 2026-10-06 — Playwright pinned to 1.56.1 so local runs use the sandbox's Chromium 141 build and CI installs the same revision.
- 2026-10-06 — Vitest + happy-dom with an in-repo `chrome.*` fake instead of sinon-chrome: typed, maintained here, no stale dependency.
- 2026-10-06 — E2E uses a local mock GitHub (127.0.0.1:4010) and a dedicated `e2e` build mode; tests are deterministic and never need a real token.
- 2026-10-06 — MIT license: permissive, standard for developer tools.
- 2026-10-06 — Minimum Chrome 116: `chrome.sidePanel.open` and the side panel API are stable from there.
- 2026-10-06 — English only in v1; strings are kept in components (i18n later).
- 2026-10-06 — github.com only in v1 (no GitHub Enterprise Server): keeps host permissions minimal.
- 2026-10-06 — Polling and notifications run in the service worker; user actions run from the side panel (immediate feedback) and then request a forced poll.
- 2026-10-06 — The OAuth App client id is injected at build time from the `PROWL_GITHUB_CLIENT_ID` repository variable; builds without it hide device flow and explain PAT sign-in, because an OAuth App can only be registered by the maintainer.
- 2026-10-06 — `github.com` is an optional host permission requested only when device flow starts; PAT users never grant it.
- 2026-10-06 — The token is stored unencrypted in `chrome.storage.local` (never `sync`): encrypting with a key stored next to it adds no protection; the threat model documents this.
- 2026-10-06 — Perf budget: side panel JS ≤ 60 KB gzip, CSS ≤ 12 KB gzip, service worker ≤ 30 KB gzip, whole extension ≤ 400 KB gzip; first list render from cache ≤ 150 ms (E2E).
- 2026-10-06 — Badge default `attention` = PRs with failing CI, changes requested, conflicts or ready to merge; red when CI fails or changes are requested.
- 2026-10-06 — Releases: release-please with `release-as: 1.0.0`; a tag-triggered workflow is the fallback if Actions may not open PRs. Assets: zip, SPDX SBOM (syft), build provenance attestation.
- 2026-10-06 — Actions are pinned to commit SHAs (Scorecard "Pinned-Dependencies").
- 2026-10-06 — Preset sections are fixed (id = kind, fixed label, enable/disable only) and normalization re-adds missing ones: the settings screen only toggles presets, and stable ids keep `snapshot.sections` keys valid across versions.
- 2026-10-06 — `pollIntervalMinutes` is capped at 60 (the brief only sets the minimum): a larger value is almost certainly corrupt data, and polling less than hourly defeats the product.
- 2026-10-06 — Settings migrations are keyed by the version they upgrade from; unversioned data counts as version 1, and data from a newer version (downgrade) is normalized best-effort instead of being discarded.
- 2026-10-06 — prLocal operations are pure reducers (state first) applied through `updatePrLocal()`, rather than one storage call each, so the notifier and badge can use them on in-memory state and one write can combine several operations.
- 2026-10-06 — Read-modify-write updates hold a Web Lock (`navigator.locks`), which the side panel and the service worker share (verified in Chromium 141), so a snooze in the panel cannot be lost to a concurrent prune in the worker; an in-context queue is the fallback.
- 2026-10-06 — Ralph iterations use Sonnet 5.5 by default and Opus 5.5 only for the GitHub fetch/mapping, diff engine, poller and security reviews, to spend the usage budget where mistakes are costly (maintainer asked whether every subagent needs Opus).
- 2026-10-06 — Dependabot ignores @playwright/test (pinned to the sandbox Chromium) and major bumps of TypeScript, Preact and @types/node (see entries above).
- 2026-10-06 — Ponytail's minimal-code ladder (MIT) is adopted in CLAUDE.md and the Ralph prompt to cut code and tokens; RTK output compression could not be installed in this sandbox (auto mode blocks downloading external binaries).
- 2026-10-06 — The GitHub client never retries or backs off: the poller owns pacing (`pollState.nextAllowedAt`), and a hidden retry would spend rate limit the poller cannot see.
- 2026-10-06 — GraphQL `errors` throw by default and `{ partial: true }` opts in to partial data: mutations return `data` with a null payload on failure, so lenient-by-default would silently swallow failed merges and reviews.
- 2026-10-06 — A rate-limited response with neither `retry-after` nor an exhausted budget gets `retryAfterSeconds: 60`, following GitHub's secondary-rate-limit guidance ("wait at least one minute").
- 2026-10-06 — Other 4xx statuses (400, 409, 422) map to `validation`, 410 to `not_found` and 451 to `forbidden`, so every HTTP failure fits the existing `ErrorKind`s without widening the model.
- 2026-10-06 — Network errors drop the thrown error instead of attaching it as `cause`: what `fetch` throws can echo request details, and "Could not reach GitHub" is all a person can act on.
- 2026-10-06 — Requests use `cache: 'no-store'`: GitHub sends `Cache-Control: max-age=60` on REST GETs, and a stale answer after a user action or a poll is worse than the extra request.
- 2026-10-06 — A bare owner in the repo filters becomes `user:owner` (and `-user:owner`): checked against the search API that `user:` matches organizations as well as users, so Prowl never has to know which kind of account an owner is.
- 2026-10-06 — Custom queries get `is:pr` prepended with no parentheses or de-duplication: GitHub's AND / OR / NOT only apply to search words (qualifiers like `is:pr` stay global, verified against the search API), and `is:pr is:pr` is accepted.
- 2026-10-06 — When a custom query already has a positive `repo:` / `org:` / `user:`, `repoInclude` is not added to the query: GitHub ORs scopes, which would widen the user's own scope; `filterByRepo` then intersects the two.
- 2026-10-06 — `filterByRepo` is the source of truth for the repo filters even though the query carries them too: GitHub ignores a positive scope that the exclusions cancel out entirely (`repo:a/b -user:a` searches all of GitHub), and the viewer-scoped presets keep that result small.
- 2026-10-06 — `validateCustomQuery` counts the 256-character limit over search words only (qualifiers and operators excluded) and the 5-operator limit over uppercase AND / OR / NOT: both measured against the search API, whose 422 messages are "The search is longer than 256 characters" and "More than five AND / OR / NOT operators were used". It also rejects operators between qualifiers only (`author:a OR author:b`), which the API refuses with a 422 as well.
- 2026-10-06 — Name re-checked (US-001): the Chrome Web Store page for the only "Prowl" extension (afjmhofmjbffpakdiiilmkcdclabhmmb, a 2012 Prowl-app notifier) no longer exists (Extpose dates the delisting 2025-09-16, the orchestrator's earlier check found 2023-08-12; both say removed) and onevcat/Prowl is a macOS app, so there is no clash and the name stays.
- 2026-10-06 — Brand mark is a cat's eye (amber almond, slit pupil) on an indigo tile: it reads at 16 px on light and dark toolbars and fits "prowl". The UI accent is the same indigo, so purple stays reserved for "merged".
- 2026-10-06 — Neutral scale is 12 steps per theme (1 = background, 12 = text) with semantic aliases; dark tokens are written twice (system and forced `data-theme`) instead of `light-dark()`, which needs Chrome 123 while the minimum is 116. A unit test keeps the blocks identical.
- 2026-10-06 — WCAG contrast is computed from tokens.css by a unit test that also checks the table in docs/design.md, so tokens and docs cannot drift.
- 2026-10-06 — Icons are Octicons v19.38.0 paths copied into `components/icons` (MIT) rather than the @primer/octicons package: no runtime dependency, tree-shakable, GitHub-familiar. The minifier drops license comments, so the license ships in `public/THIRD_PARTY_NOTICES.txt`; Preact and @preact/signals notices are not in it yet (release story).
- 2026-10-06 — Menus use `position: fixed` with JS placement (flip, clamp, follow on scroll) instead of the Popover API plus CSS anchor positioning, which needs Chrome 125.
- 2026-10-06 — Dialog builds on native `<dialog>` + `showModal()` (top layer, inert page) and adds an explicit Tab trap and focus restore, because Tab can otherwise leave a modal dialog for browser UI.
- 2026-10-06 — Under `prefers-reduced-motion` the spinner keeps turning at half speed (it is the only progress signal); transitions and the skeleton shimmer stop.
- 2026-10-06 — Design-system components are imported from their own modules (no `ui/index.ts` barrel) so a view only bundles the CSS it uses.
- 2026-10-06 — The 128 px icon has 16 px transparent padding (Chrome Web Store guideline); 16–48 px icons use the full canvas for legibility.
- 2026-10-06 — The list query leaves team reviewers out of `requestedReviewers`: every `Team` field needs `read:org` (or `read:discussion`) and selecting one fails the whole query for a `repo`-only token (cli/cli#812); PR details can read teams from REST `GET /repos/{o}/{r}/pulls/{n}/requested_reviewers`, which needs only `repo`.
- 2026-10-06 — The check state is derived from `checkRunCountsByState` / `statusContextCountsByState`, not `statusCheckRollup.state`: the rollup reports a cancelled run as a failure until it is replaced, and its value changes when `contexts` is selected in the same query; CANCELLED, STALE, SKIPPED and NEUTRAL count as neutral, as model.ts defines.
- 2026-10-06 — Search pages hold 50 PRs, cursor-paginated up to `maxPerSection`: the point cost equals one page of 100, and smaller pages keep the nested reads clear of GitHub's 10 s execution limit (504s are reported for 100-PR pages with check rollups).
- 2026-10-06 — A poll's requests run one at a time: GitHub's advice for avoiding secondary rate limits is to make requests serially, and a poll is a handful of requests.
- 2026-10-06 — Searches append `sort:updated-desc` unless a custom query has its own `sort:`, so the `maxPerSection` PRs kept are the most recently updated rather than best-match.
- 2026-10-06 — Only a custom section can fail alone (invalid query, or GitHub refusing it as validation / not_found / forbidden / graphql); a preset's failure and any unauthorized / rate_limited / network / server failure throw for the whole poll, because presets differ only by Prowl's own qualifier, so their failure means the shared filters or GitHub are at fault.
- 2026-10-06 — PRs that left every section stay in `snapshot.pullRequests` (in no section) only once merged or closed, so the diff sees the final state and who caused it; still-open ones are dropped, and merged or closed ones are never looked up again, so `ProwlNodes` stays small.
- 2026-10-06 — `fetchPullRequests` does not query the viewer: the poller takes it from `auth` (validated at sign-in), keeping the poll's queries to PR fields.
- 2026-10-06 — Invalid label colors fall back to `ededed`, a light neutral grey, rather than dropping the label.
- 2026-10-06 — A PR that is new in the next snapshot produces no events (no baseline), like one that left the scope: enabling a section or a new review request must not replay the PR's history as notifications.
- 2026-10-06 — `comment_new` also requires the latest issue comment to be newer than the previous one: `commentCount` includes review comments, which review events already report, and the viewer's own review comments would otherwise notify them whenever someone else wrote the last issue comment.
- 2026-10-06 — Event ids are `<pr id>:<type>:<key>` (head SHA for CI, ready to merge, merged and closed; review id; latest comment time) without the poll time, so a poll repeated after a worker restart dedupes; a re-run failing again, or a PR closed twice, on the same commit is reported once.
- 2026-10-06 — `merged` / `closed` with an unknown actor (`closedBy` null: deleted account, or a PR closed while still in a custom search, which carries no ClosedEvent) is reported: missing someone else's merge is worse than a rare note about one's own close.
- 2026-10-06 — CI and ready-to-merge events take `next.fetchedAt` as `at` (the snapshot has no check completion time); events are sorted oldest first by `Date.parse`, since `toISOString()` and GitHub timestamps differ in their milliseconds.
- 2026-10-06 — The diff returns nothing when `prev` was taken for another account, so an account switch that left the old snapshot behind cannot notify one account about another's PRs.
- 2026-10-06 — `ci_passed` follows the acceptance criterion literally (previous poll `failure`), so failure -> pending -> success is not reported; the poller (US-007) can pass a `prev` with the last settled check state of pending PRs rather than the diff keeping history.
- 2026-10-06 — Panel routing: signed out is always onboarding; signed in shows onboarding only when the hash is `#/onboarding` (so US-011 / US-021 can reuse it to re-authenticate) and unknown hashes mean the list; the route is derived from `auth`, so signing in or out switches the view without a navigation call.
- 2026-10-06 — `hydrateStore()` subscribes before it reads and lets a change that arrives during the read win: a stale read of `pollState.inFlight` would otherwise leave the refresh spinner stuck until the next poll.
- 2026-10-06 — `navigate()` updates the hash signal itself instead of waiting for `hashchange`, which browsers dispatch as a later task; the listener still handles hashes changed from outside.
- 2026-10-06 — `sendToBackground()` swallows every failure of `runtime.sendMessage`: with no receiver (worker not listening yet) the panel cannot do anything useful, and the next storage write brings it up to date anyway.
- 2026-10-06 — The panel opens URLs only through `openGitHubUrl`, which compares the URL's origin with `env.webUrl` (a prefix check would accept `https://github.com.evil.example`).
- 2026-10-06 — "Updated" uses `snapshot.fetchedAt` (when the data was fetched), not `pollState.lastSuccessAt`; relative times are "just now", "N min ago", "N h ago", "N d ago" (`src/lib/time/relative.ts`, reused by the PR cards).
- 2026-10-06 — After a route change `<main>` takes focus and carries the view's name, so keyboard and screen reader users land in the new view; the header's settings button turns into "Back to pull requests" while in settings.
- 2026-10-06 — Until US-011 adds sign-out, the account menu only links to the GitHub profile; views other than the shell (onboarding, list, settings) are placeholders that later stories replace.
- 2026-10-06 — `ci_passed` now compares with the state CI last concluded (supersedes the "literal" entry above): `Snapshot.settledChecks` carries the last non-pending state of pending PRs, built by `carrySettledChecks` next to the diff, because the usual fix flow (failure -> pending -> success) was otherwise never reported; keeping it in the snapshot avoids a second storage key that could drift from it.
- 2026-10-06 — `sectionErrors` and `settledChecks` are optional `Snapshot` fields (absent = none) so existing builders and seeded test snapshots stay valid; the poller always writes both. Section errors live in the snapshot, not `pollState`, because they describe what that snapshot is missing.
- 2026-10-06 — Backoff is `interval × 2^failures` with `failures` counting the failure just recorded (first retry after two intervals, since the alarm already fires every interval), capped at 30 min, with up to 25% jitter subtracted so the cap is never exceeded.
- 2026-10-06 — A forced poll (refresh, re-auth) skips a backoff and retries a rejected token, but never a rate-limit wait (after `rate_limited` or a success with < 100 points left): spending more of an exhausted budget only prolongs the lockout.
- 2026-10-06 — Waits longer than one hour are capped when stored and ignored when read: GitHub's primary limit resets within the hour, so a longer wait means a bogus `retry-after` or a clock set back, which must not stall polling for hours.
- 2026-10-06 — `unauthorized` clears the alarm instead of leaving it to fire and skip; every poll that runs re-creates the alarm, so a forced poll after re-authentication resumes the schedule without a separate "start" message.
- 2026-10-06 — Single-flight is an in-memory promise: only one service worker instance exists, and a stored `inFlight: true` seen by a skipped poll can only be left by a worker that stopped mid-poll, so it is reset.
- 2026-10-06 — A poll whose token is no longer the stored one (sign-out or another account mid-poll) is dropped before it writes; it restarts for a new account, otherwise clears what sign-out clears. The few-ms window between that check and the write is accepted (a shared lock with the panel's sign-out would close it).
- 2026-10-06 — While any section failed to load, pruning keeps the local state (mute, snooze, seen) of PRs absent from the snapshot: they may only be hidden by the failing section, and losing a mute is worse than keeping a stale entry for one more poll.
- 2026-10-06 — The worker answers a `BackgroundRequest` (with nothing) only once it is handled, so a sender awaiting `sendMessage` knows a forced poll is finished; the E2E `poll()` helper relies on it, and the panel's fire-and-forget calls are unaffected.
- 2026-10-06 — `ensureSettings()` is not called on install yet: every read normalizes, and with no migrations there is nothing to persist; a settings change only reschedules the alarm (the settings screen can ask for a poll when sections change).
- 2026-10-06 — Poll failures that are not `GitHubError`s (a bug, data the mapper cannot handle) are stored as `server` with a generic message and logged with `console.error`, so the panel shows an error instead of a spinner stuck on `inFlight`.
- 2026-10-06 — Views other than the shell (list, settings) are placeholders that later stories replace.
- 2026-10-06 — Fine-grained tokens are accepted but flagged: GitHub has no Checks permission for them (documented limitation, confirmed by GitHub support in 2025), so check runs are unreadable and CI can show as none; classic with `repo` is recommended. Verified against GitHub's docs, not against a live fine-grained token (none was available), so the copy says CI status "can be missing".
- 2026-10-06 — Token creation links use GitHub's template URLs: classic `scopes=repo&description=Prowl`, fine-grained `name`, `description` and `pull_requests=write&contents=write&actions=write&statuses=read` (Metadata read is implicit); write is pre-selected because approving, merging and re-running need it, and the form stays editable.
- 2026-10-06 — A classic token without `repo` (or with no scopes) still signs in, with a warning toast: it works for public repositories, so refusing it would be wrong, and a toast keeps onboarding one step. A token the client cannot classify by prefix (old 40-digit tokens) gets the scope warning only when GitHub sends `x-oauth-scopes`.
- 2026-10-06 — Sign-in validates with both `viewer` (the API Prowl polls with) and `GET /user` (scopes), in parallel; `client.restResponse` returns headers instead of widening `rest`, so existing callers are untouched.
- 2026-10-06 — Sign-out keeps `settings` and `prLocal`: neither holds a secret, and a user who signs back in expects their sections, filters and snoozes. Only `auth`, `snapshot` and `pollState` go.
- 2026-10-06 — The Dialog's `<header>` and `<footer>` became `<div>`s: inside a `<dialog>` axe reads them as banner / contentinfo landmarks nested in another landmark (first caught by the sign-out confirmation).
- 2026-10-06 — Events dropped during quiet hours (or by a toggle, mute or snooze) are discarded, not deferred: the snapshot has moved on and the list still shows the PR, and a digest of old news when quiet hours end would be noise; they are also not marked as reported, so the same event still notifies if it recurs while allowed.
- 2026-10-06 — A quiet window with `start === end` is empty rather than all day: the less surprising failure for a misconfigured window is a notification, not silence.
- 2026-10-06 — The reported event ids live in `chrome.storage.session` (newest 300, event id -> PR URL), not `local`: dedupe only has to outlive a worker restart, and after a browser restart the stored snapshot is the baseline, so nothing is replayed; the same map is how a click finds its PR. A re-run that fails again on the same commit is therefore reported once (the documented price of ids without the poll time).
- 2026-10-06 — More than 3 events in one poll collapse into one summary ("N pull request updates" listing the first PRs); a click on it only clears it, because it has no single PR and `sidePanel.open` needs a window id obtained asynchronously, which risks losing the user gesture (not verified, so not shipped). The action icon opens the panel.
- 2026-10-06 — The notifier never rejects and runs inside the poll after the snapshot is stored: a notification failure (no display, permission revoked) must not fail the poll or its backoff. The worker's URL allowlist (`isGitHubUrl`) is a private copy in `notifier.ts` next to the panel's `openUrl.ts` one; extract it into `src/lib` once a third caller exists.
